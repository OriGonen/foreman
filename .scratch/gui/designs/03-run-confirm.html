03 · Starting a run: the confirmation

Starting a run costs money, so Start run… always opens this first, and nothing is spawned until the person confirms. It shows the three budgets: iterations (set here, as <n> or --unlimited), FOREMAN_MAX_COST_USD and FOREMAN_MAX_MINUTES (read from foreman dry-run --json, i.e. foreman.conf and the environment; take c can change them for this one run, under Advanced options, by passing them as environment variables to that run — foreman.conf is never written). It also shows the exact command that will run. Esc or Cancel spends nothing.

Pick: c · the bill with the tiles, a merge asked for at sign-off: a's receipt (what it will run on, how far it can reach, the exact command, the button that says the most it can spend) with b's three tiles — iterations, spend cap, time cap — added to it. By default only the iteration count is editable; the batch, where it starts and where it can reach are shown, and everything else sits behind Advanced options, where the spend cap, the time cap and the live view become editable for this run. Every field has a ? that says what it does, for example whether the time cap is per iteration or for the whole run (the whole run; c2 has every text). a and b are kept below as drawn.
