05 · How a run ends: exit 0, 10, 20, 30

Each take shows all four endings. What the app knows comes from the run's footer in foreman-runs.log (# complete, # paused: … + # next up: …, # stopped: needs a human + the new # reason: …, # stopped: waiting on a human — …), and from the exit code when the app started the run itself. Reopened later, it shows the same thing, because it is all in the log.

Resuming is rerunning the same command, so Resume… opens the same confirmation as Start run. The free next steps (report, dry run, doctor) say so.

Pick: a · banner on the run. After a stop the first question is "what happened", and a keeps the run's iterations underneath the banner to answer it; the four endings differ only in the banner's colour, words and buttons, so the next step is always in the same place. b's scenes are handsome and the right idea for the overview's empty state, but they replace the evidence with a picture.
