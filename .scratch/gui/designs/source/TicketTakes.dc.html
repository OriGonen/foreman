02 · Ticket detail, and the handoff editor

One ticket: its status line, Blocked by:, Checks: (or which followup checks it), Handoff:, the ticket text, and the progress.txt notes that mention it. For a human ticket, the one thing the app writes: the handoff file named on its Handoff: line, inside the repo, nowhere else.

The ticket itself is never edited here. Marking a human ticket done is flipping its status line in the person's editor (Open ticket in editor). All ticket, notes and handoff text is shown as text, never as HTML: the Preview of the ticket is drawn from a small fixed set of elements (heading, bold, inline code, bullets, check boxes, paragraphs) built as DOM nodes, so a <script> or a link in a ticket is shown as the characters it is. A Preview | Markdown switch above the ticket text shows it either way (Preview by default).

When the ticket is done, the page also shows what its runs cost and took (b3): model, runtime, cost, iterations, turns and tokens.

Pick: b · ticket page, with two additions asked for at sign-off: (1) a Preview | Markdown switch over the ticket text, Preview by default (b shows Preview, b2 shows Markdown), and (2) a finished ticket shows its run stats — model, runtime, cost and more (b3). The handoff file answers the ticket's criteria, so the two need to sit side by side at full height; the drawer in a squeezes both into 470px and hides the order behind a scrim for no gain. b1 shows the same page for an agent ticket, so one layout covers both.
