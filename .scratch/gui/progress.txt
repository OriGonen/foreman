## 09 — `foreman stop --now` (implemented; **the Windows spike and by-hand steps are NOT done**)
- Built: `stop --now` in lib/foreman-control.sh = write `<ctl>/stop`; SIGINT to the loop and every process below it (walk of `/proc/*/stat`, `ps` fallback); after `FOREMAN_STOP_GRACE`s (5) force what is still below the loop (`taskkill /F /T` on its winpid, else `kill -9`; never the loop); wait `FOREMAN_STOP_WAIT`s (60) for the loop to exit, exit 0 / else 1. Loop: `check_stop_file` (calls `on_interrupt`) at the top of each iteration and after each agent pipeline (turn and checkpoint). No stop file = one `[ -e ]`, nothing else changes. Notes: `.scratch/gui/notes/09-stop-now.md`, harness `09-spike.sh`.
- Linux findings (measured): SIGINT to the loop alone does nothing (trap waits for the foreground agent); `taskkill`/`kill -9` of the loop skips the handler and orphans the agent; only INT-to-all (or stop file + agent ended) is Ctrl-C. A loop started by `&` in a script ignores SIGINT entirely, so the stop file is what stops it.
- Test-driven (smoke-json.sh): stop file pauses as Ctrl-C (exit 10, marker, footer); detached run (node spawn, detached/windowsHide/stdin ignored) + `stop --now`: exit 10, footer identical to a Ctrl-C run's, marker + work stay, no `sleep`/feed left, next run opens with a review turn; INT-ignored run; usage/refusals. Mutation-checked: no stop-file check, no force-kill. Fake exec: `hang-dirty`, `stop-file-dirty`, checkpoint `stop-file`.
- Decision: Ctrl-C during a checkpoint turn ends as needs-human (20) today, so a stop there does too (parity, not improvement).
